# settings-page

`/settings/<section>` (also `/settings`): the owner's hub, styled like iOS Settings: on a phone `/settings` is a list of sections (grouped rows with an icon tile and chevron) and a section page shows only its pane with a "‹ Settings" back link; from md up a rail of sections sits beside one pane. Settings are rows in `t-group-lined`s: switches are `t-switch`, numbers a pill stepper (`cards.ts` in `apps/settings`); Tags and Memory are rows that slide open. Chats is its own page at `/chats` (`apps/chats`).

- `frame.ts`: the app's `layout`: header, rail and pane column. The router keeps it and swaps only the pane; the current rail link is styled by `aria-current` (`settings.css`). The home page renders a `data-settings-home` marker, which `settings.css` reads with `:has()` to show only the rail on a phone and to highlight the first section on desktop.
- `index.ts`: one component per route: the default (home), `Section` (`ctx.params.section`) and `JobRuns` (`/settings/background/<job>`).
- `sections.ts`: `sections()`, the rail: this app's own sections (Account, Preferences, Memory, Instructions, Background Work) plus one per app whose `settings.ts` has a `pane` (`list()` from `apps/settings`), by `order`. A section's id is the app folder (`/settings/notifications`, `/settings/theme`).
- `account.ts`, `account-username.ts`, `account-password.ts`: the Account section, read with `account()` and changed with `ravel.account` (see `.ravel/account.md`). A hero, then one group: Email (read-only, the core has no email change), Username and Password (each opens a sheet), a Claude row (status from `auth()`, "Log in to Claude again" runs `ravel.claude.login()` then `submitCode()` inline), then log out of this device / other devices. The Time zone group (`zone.ts`) shows where the owner is now and their home zone, with "Use … as home" and a picker; devices report their zone through `zone.report` in the root `app.ts` (`reportZone` from `@app/settings/api.ts`). Password text never goes through signals, the database or the chat. `username.ts` holds the username rules, tested in `username.test.ts`.
- `preferences.ts`: the values of every app without a pane, one group per app.
- `settings.ts`: this app's own setting, tab bar haptics (read by the root `app.ts` for `ios`).
- `api.ts`: `readInstructions`, `listMemories` (used by `apps/patterns`) and `settings`.
- `memory.ts` + `memory-files.ts`: view Claude's memory files (`claude/projects/<space path>/memory/`); Save and Forget start the `memory-change` job (`memory-change.ts`, a Claude run) because the site's own writes to that folder never reach the real files; the list is live and shows a spinner while it runs.
- `instructions.ts` + `instructions-file.ts`: `CLAUDE.md` is read-only (rendered markdown) with "Ask Claude to improve it" / "Ask for a change…" buttons that open the chat; "Edit by hand" reveals a text editor, and each save keeps the previous text in `private/claude-md.previous` for Revert.
- `jobs.ts`: the Background Work pane in Settings (`/settings/background`): the jobs every app registers in its `app.ts`, in short groups (`GROUPS`: Sync, Sorting and tags, Planit, Reminders, Assistant and chats, Housekeeping, Other), one swipe row each (name, a one-line status with last run and next run, an enabled switch; tapping the name opens the job page). Swipe or ⋮ for Run now, Preview and Ask AI. Jobs, their descriptions and switches come from `apps/settings` (`listJobs`, `setJobEnabled`); `job-state.ts` holds the state helpers (last finished run apart from the queued/running one) and the `run`, `toggle` and `cancel` actions both fragments export.
- `job-runs.ts`: the `/settings/background/<name>` pane: description, an Enabled switch, Next run / Last run rows, Run now / Preview / Ask AI rows, then the last 30 runs with Stop and each report (Reply opens a new chat prefilled with a pointer to that run). `run-view.ts` renders one run.

- Appearance is `apps/theme/appearance.ts`, Notifications `apps/notifications/index.ts`, Tags `apps/tags/pane.ts`, Patterns `apps/patterns/pane.ts`: each app's `pane`.
- To add a setting, declare it in the app's own `settings.ts` (see `apps/settings/README.md`).
