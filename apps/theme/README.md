# theme

The site's themes: the skin for `apps/design-system`, which owns the CSS classes and writes `theme/`. **Ravel** is the theme every site starts with and ships in this app (`themes/ravel/`); the owner's own themes (Highland) live in the private `apps/my-themes`, so publishing this app publishes only the framework and Ravel. Every theme has a light and a dark mode: the mode is one site-wide pick, saved in `theme_picks`, and the chosen theme is `theme.name` in the `settings` table. Both are set in Settings → Appearance (`/settings/theme`): `appearance.ts` is the pane (declared in `settings.ts` with the `auto` switch), holding `picker.ts` (mode and theme grid) and `dials.ts` (a theme's dials, shown only for a theme that has some).

- `site-theme.ts`: `listThemes`, `currentTheme`, `setTheme`, `themeCss()` (the active theme's variables for both modes under `:root[data-mode=light|dark]`, a `.theme-preview-<name>` class per theme and mode for the picker, then its extra rules and `@import` lines), `themeTokens()` (the variables and `mode` for the iOS app), `themeClient()` (`theme.client.ts`, which loads the page-change motion from `apps/shell/transition.client.ts` when that app is installed and, for a theme with scenery, imports `dials.client.ts` (sets `window.__themeDials`) and the theme's `extra.client.ts`) and `themeThread()` (the `--r-t1..3` thread colors).
- `skin.ts`: hands those four to the design system (`plugs: { "design-system": "./skin" }` in `app.ts`). Anything that changes the theme, the mode or a dial calls `writeTheme()` from `@app/design-system/api.ts` (the picker, the dials, Branding, `schedule.ts`).
- `api.ts`: what other apps use: `getPick` / `setPick` and `writeTheme`.
- `backdrop.ts`: the backdrop every page sits on (`backdrop` in the root `app.ts`): `.t-backdrop` and `.t-glow`. Scenery draws into `.t-backdrop`. The iOS app shows it at `/_backdrop` behind its native chat.
- `installed.ts`: finds the fixed themes (`installedThemes()`, `themeFolder()`): any folder `apps/<app>/themes/<name>/` with `vars.light.css` and `vars.dark.css`; `theme.json` is optional (without it the theme takes its folder's name and has no dials). This includes `apps/theme/themes/<name>/`, where themes lived before they moved out, so an installed copy's own themes keep working (`name`, and optionally `dials`, a list of `{kind,label,hint,min,max,fallback}`). This app never imports a theme, so installing or removing one is just adding or deleting its app.
- `themes/ravel/` here, `apps/my-themes/themes/<name>/`: a fixed theme's files: `vars.light.css` and `vars.dark.css` (the same variables, plus `--r-t1..3`), optional `extra.css` (written with the theme's own variables so one file serves both modes) and `extra.client.ts` (scenery; reads `window.__themeDials` and rebuilds when `window.__themeRefresh()` is called). `apps/my-themes/themes/highland` is a sunny day or starry night hillside with grazing cows (the `cows` dial), clouds, flowers or fireflies, a gondola, and a hop and a moo when you tap a cow.
- `theme-dials.ts`: the numeric dials of a theme (`themeDials`, `allDials`, read from `theme.json`); `picks.ts` saves and validates them (`savePick`, `dialValues`) along with `mode`.
- `picks.ts`: the `theme_picks` table (`getPick`, `setPick`, `currentMode`).
- `preview.ts`: tries a look in your browser alone, leaving the owner's theme as it is: from the space root, `RAVEL_SPACE=$PWD deno run -A apps/theme/preview.ts highland mode=light cows=2` (a theme and/or `kind=value` picks; the rest stay as picked) writes `theme-preview/`, then reload. `--clear` deletes it when you're done. Use it for every check of a theme, palette, style, mode or dial; save picks only when the owner asks for that look.
- `sun.ts`, `zone-place.ts` and `schedule.ts`: see below. `zone-place.ts` turns a time zone into a latitude and longitude (a table of main cities; unlisted zones use their offset's meridian), which `sun.ts` needs.

**Ravel** (`themes/ravel/`) is a soft blue, green and clay gradient behind rounded, shadowed cards (`--rv-*` variables: the gradient stops, glass and dot colors; `extra.css` draws the gradient in `.t-backdrop`).; picking a theme calls `appChanged()` so open pages reload with the right bar. Its look is written up in `themes/ravel/README.md`.

**Merging an update from `ravel-plugins`: keep the owner's edits to `themes/ravel/vars.*.css` and `extra.css`, and never delete another folder in `apps/theme/themes/`; those are the owner's themes.** To add a theme: add a folder in `apps/my-themes/themes/` (or another app's `themes/`) with `theme.json` and both var files (a test checks both modes define the same variables, the radii and the thread colors). With one theme the picker hides itself.

Every page is themed.

`schedule.ts` (job `theme-schedule`, every 10 minutes, switch `theme.auto` in Settings → Appearance): sets the site-wide mode (the `mode` pick, so every theme) to dark from sunset to sunrise where the owner is (`sun.ts`) and light otherwise. It only acts when sunrise or sunset passes, so a mode picked by hand stays until the next crossing. 

A theme sets `--radius-card`, `--radius-field` and `--radius-pill`. The iOS-style classes in `apps/design-system/base.css` read them: `t-group-lined` (a rounded group of rows with inset separators; `--t-inset` moves the line, `t-group` drops it), `t-pill` / `t-field` (add to a chip or input to take the theme's capsule / field corners), `t-title`, `t-check`, `t-switch`, `t-expand` and `t-glass`. A new theme must set the same variables (a test checks them). Todo is the reference for how they fit together.

The web sheet (`#ravel-sheet`, opened by `ravel.sheet`) slides up on a phone and fades in on a wide screen (`t-sheet-up` / `t-sheet-pop` keyframes in `apps/design-system/base.css`); closing is instant. The preview browser used for checking pages serves a `<style>` that zeroes every animation duration, so to see motion there, run `document.styleSheets[1].disabled = true` first.

`design-system-page.ts` is the full page `/design-system` (route in `app.ts`): every colour, shape and design-system component drawn in the current theme and mode, with a "‹ Settings" link back to Appearance. Settings → Appearance ends with a row that opens it.
